## Project Overview

This is the **STM32WB55 FreeRTOS firmware** for the Smart Kuweta IoT Cat Litter Monitor project. The firmware runs on the P-NUCLEO-WB55 development board and implements real-time motion detection, timestamping, and UART communication with an ESP32-CAM.

**Key Responsibilities:**
- GPIO interrupt handling (PIR motion sensor on HC-SR501)
- RTC-based visit duration timing
- UART serial communication with ESP32-CAM for trigger signals
- Three on-board button handling and three RGB LED control
- USB and BLE infrastructure initialization

## Build System

### CMake Build (Recommended)

The project uses CMake with ARM cross-compilation toolchain.

**Prerequisites:**
- arm-none-eabi-gcc (GCC ARM Embedded Toolchain)
- cmake (minimum 4.1)
- make

**Build Commands:**

```bash
# Debug build (minimal optimization, debug symbols)
cmake -DCMAKE_BUILD_TYPE=Debug -B cmake-build-debug
make -C cmake-build-debug

# Release build (full optimization)
cmake -DCMAKE_BUILD_TYPE=Release -B cmake-build-release
make -C cmake-build-release

# Clean build
rm -rf cmake-build-debug && mkdir cmake-build-debug
```

**Output Artifacts:**
- `cmake-build-debug/smart-kuweta-stm32.elf` — executable (for GDB debugging)
- `cmake-build-debug/smart-kuweta-stm32.hex` — Intel HEX format (for STM32CubeProgrammer)
- `cmake-build-debug/smart-kuweta-stm32.bin` — binary image (for UART/SWD flashing)
- `cmake-build-debug/smart-kuweta-stm32.map` — linker map file

### STM32CubeIDE Alternative

The project was generated by STM32CubeIDE (6.16.1) from an .ioc file. The CMakeLists.txt is auto-generated from CMakeLists_template.txt. If peripherals are reconfigured in STM32CubeMX:
1. Edit `smart-kuweta-stm32.ioc` via STM32CubeIDE
2. Let CubeMX regenerate C files in `Core/` and `Drivers/`
3. Regenerate CMakeLists.txt: use the CubeIDE build or manually update from template

## Architecture

### Task Design (FreeRTOS CMSIS-RTOS V2)

The firmware implements a multi-task RTOS architecture:

```
FreeRTOS Scheduler
├── defaultTask (Priority 24)
│   └── Blinks LED_BLUE every 500ms
│       (Placeholder for application logic)
└── [Future Tasks]
    ├── PIRTask — Motion detection via GPIO EXTI
    ├── TimerTask — RTC-based visit duration
    └── UARTTask — ESP32-CAM communication
```

**Current State (Work in Progress):**
- Only `defaultTask` is implemented (blinks blue LED)
- User code sections (`USER CODE BEGIN/END` blocks) are reserved for future task implementations
- Synchronization primitives (queues, semaphores, mutexes) not yet configured

**FreeRTOS Configuration** (`Core/Inc/FreeRTOSConfig.h`):
- Heap: 3 KB (tight; must expand if adding memory-intensive tasks)
- Tick rate: 1000 Hz
- Max priorities: 56
- Heap implementation: Heap_4 (fragmentation-resistant)
- CMSIS-RTOS V2 wrapper layer enabled

### Peripheral Configuration

**GPIO Pins Used:**
- PC13: System wakeup (SYS_WKUP2)
- PA13, PA14, PB3: JTAG/SWD debug interface (hardware-locked)
- PA11, PA12: USB D-/D+ (reserved for future USB support)
- PB6, PB7: USART1 TX/RX (ESP32-CAM serial communication)

**Clock Configuration:**
- **SYSCLK Source**: MSI (Multi-Speed Internal oscillator) @ ~4 MHz
- **HSI**: Enabled for SMPS (Switched-Mode Power Supply)
- **PLL**: Disabled (MSI used directly; conservative for power efficiency)
- Voltage scaling: Scale 1 (full performance)

**Enabled HAL Modules:**
- GPIO, DMA, UART, EXTI, Flash, PWR, RCC, Cortex
- Disabled: ADC, I2C, SPI, TIM (not yet needed)

**BSP Features Initialized:**
- LEDs: `LED_BLUE`, `LED_GREEN`, `LED_RED` (GPIO control)
- Buttons: `BUTTON_SW1`, `BUTTON_SW2`, `BUTTON_SW3` (EXTI interrupt mode)
- Serial: COM1 @ 115200 baud (8 bits, 1 stop, no parity)

### Memory Layout

**Linker Script:** `STM32WB55RGVX_FLASH.ld`

```
FLASH (512 KB):
  0x08000000 — ISR vectors
  0x08000040 — Program code & constants

RAM (192 KB, M4 core):
  0x20000008 — Initialized globals (.data)
  0x20000xxx — Zero-initialized globals (.bss)
  0x20000xxx — Heap (grows upward)
  0x2002xxxx — Stack (grows downward)

RAM_SHARED (10 KB, M0+/M4 IPC):
  0x20030000 — BLE/mailbox coordination
```

**Stack & Heap:**
- Per-thread stack: configured in task attributes (`defaultTask` = 128 words = 512 bytes)
- FreeRTOS global heap: 3 KB total
- Linker min heap: 0x200, min stack: 0x400

### Hardware Blocks (STM32WB55RG)

**Dual-Core (Cortex-M4 + Cortex-M0+):**
- M4 core: Application FreeRTOS + HAL drivers (this firmware)
- M0+ core: BLE radio stack (not in scope)
- **HSEM**: Hardware semaphore for M4 ↔ M0+ synchronization
- **IPCC**: Mailbox for inter-processor messaging

**Peripherals in Use:**
- RCC: Clock & reset
- GPIO: Port A, B, C
- EXTI: Button interrupts
- UART/USART: USART1 for ESP32-CAM
- Flash: For future firmware updates

**Peripherals Not Yet Configured:**
- RTC (needed for visit timestamping)
- ADC, I2C, SPI, TIM
- Cryptography accelerators

## Key Source Files

### Entry Point & System Initialization

**`Core/Src/main.c`**
- `main()`: HAL init → clock config → peripheral init → FreeRTOS scheduler start
- `SystemClock_Config()`: MSI clock tree setup
- `PeriphCommonClock_Config()`: SMPS clock routing
- `MX_GPIO_Init()`: GPIO alternate functions (USB pins)
- `Error_Handler()`: Fatal error handler (disables IRQs, infinite loop)
- `StartDefaultTask()`: FreeRTOS task entry (blinks LED_BLUE every 500ms)

**`Core/Src/system_stm32wbxx.c`**
- `SystemInit()`: Very early boot initialization (before main)
- `SystemCoreClock`: Global variable for HAL timing calculations

### Interrupt & Exception Handling

**`Core/Src/stm32wbxx_it.c`**
- Exception handlers: NMI, HardFault, MemManagement, BusFault, UsageFault
- `EXTI0_IRQHandler`, `EXTI1_IRQHandler`, `EXTI4_IRQHandler`: Button interrupts (future: PIR sensor)
- **FreeRTOS handlers** (SVC, PendSV, SysTick): Mapped via FreeRTOSConfig.h

**IRQ Priorities:**
- Kernel interrupts (SysTick, PendSV, SVC): priority 15 (lowest, safe for FreeRTOS)
- User interrupts (EXTI): priority 5 (can preempt lower-priority user code)
- Exceptions (NMI, HardFault): non-configurable (highest)

### HAL & Board Support

**`Core/Src/stm32wbxx_hal_msp.c`**
- `HAL_MspInit()`: HAL initialization callback (empty by default)
- Per-peripheral callbacks: Templates for ADC, UART, etc.

**`Drivers/BSP/P-NUCLEO-WB55.Nucleo/stm32wbxx_nucleo.c`**
- `BSP_LED_Init()`, `BSP_LED_On()`, `BSP_LED_Off()`, `BSP_LED_Toggle()`
- `BSP_PB_Init()`: Button initialization with EXTI
- `BSP_COM_Init()`: UART setup for serial communication

### FreeRTOS & Middleware

**`Core/Inc/FreeRTOSConfig.h`**
- Central configuration: heap size, tick rate, priority levels, etc.
- CMSIS-RTOS V2 wrapper settings

**`Core/Src/app_freertos.c`**
- Placeholder for FreeRTOS-specific initialization (currently empty)

**`Middlewares/Third_Party/FreeRTOS/`**
- Standard kernel (v10.6.2)
- CMSIS-RTOS V2 wrapper layer
- ARM Cortex-M4F portable port

### System-Level Files

**`Core/Src/syscalls.c`** & **`sysmem.c`**
- libc integration for `printf()`, `malloc()`, etc.
- Heap management separate from FreeRTOS heap

**`STM32WB55RGVX_FLASH.ld`**
- Linker script: memory regions and section placement

## Development Workflow

### Adding a New Task

1. **Declare task entry function** (in appropriate source file):
   ```c
   void PIRTaskEntry(void *argument) {
       for(;;) {
           // Task logic
           osDelay(pdMS_TO_TICKS(100));
       }
   }
   ```

2. **Create task in main.c** (in `USER CODE BEGIN RTOS_THREADS` section):
   ```c
   osThreadAttr_t pir_attr = {
       .name = "PIRTask",
       .priority = osPriorityAboveNormal,
       .stack_size = 256 * 4  // 256 words
   };
   pirTaskHandle = osThreadNew(PIRTaskEntry, NULL, &pir_attr);
   ```

3. **Add inter-task communication primitives** (in main.c before scheduler start):
   ```c
   osMessageQueueId_t motionQueue = osMessageQueueNew(10, sizeof(uint32_t), NULL);
   ```

4. **Rebuild and flash:**
   ```bash
   cmake -DCMAKE_BUILD_TYPE=Debug -B cmake-build-debug
   make -C cmake-build-debug
   ```

### Handling GPIO Interrupts (PIR, Buttons)

1. **Reconfigure pin in STM32CubeMX** (.ioc file via STM32CubeIDE):
   - Set pin mode to GPIO_EXTI
   - Choose EXTI line and priority
   - Regenerate code

2. **Implement handler in stm32wbxx_it.c:**
   ```c
   void EXTI4_IRQHandler(void) {
       HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_4);
   }

   void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin) {
       if (GPIO_Pin == PIR_PIN) {
           // Queue event to PIRTask
           osMessageQueuePut(motionQueue, &event, 0, 0);
       }
   }
   ```

3. **Process in task:**
   ```c
   void PIRTaskEntry(void *argument) {
       uint32_t event;
       for(;;) {
           if (osMessageQueueGet(motionQueue, &event, NULL, osWaitForever) == osOK) {
               // Handle motion event
           }
       }
   }
   ```

### Enabling RTC for Timestamping

1. **Enable RTC in STM32CubeMX** (currently disabled):
   - Configure RCC to enable RTC clock
   - Set RTC mode (Binary, 12/24H, etc.)
   - Regenerate code

2. **Initialize in main.c:**
   ```c
   RTC_TimeTypeDef sTime = {0};
   sTime.Hours = 12;
   sTime.Minutes = 0;
   sTime.Seconds = 0;
   HAL_RTC_SetTime(&hrtc, &sTime, RTC_FORMAT_BIN);
   ```

3. **Read time in tasks:**
   ```c
   RTC_TimeTypeDef time;
   HAL_RTC_GetTime(&hrtc, &time, RTC_FORMAT_BIN);
   // Use time.Hours, time.Minutes, time.Seconds
   ```

### UART Communication with ESP32-CAM

**Initialization** (already done in main.c):
```c
BspCOMInit.BaudRate = 115200;
BSP_COM_Init(COM1, &BspCOMInit);
```

**Transmit data:**
```c
uint8_t cmd[] = "CAPTURE\r\n";
HAL_UART_Transmit(&huart1, cmd, sizeof(cmd), 100);  // Blocking
```

**Receive data** (interrupt-driven, recommended for RTOS):
```c
// In main.c init:
uint8_t rx_buffer[64];
HAL_UART_Receive_IT(&huart1, rx_buffer, sizeof(rx_buffer));

// RX complete callback:
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    if (huart->Instance == USART1) {
        osMessageQueuePut(uartQueue, huart->pRxBuffPtr, 0, 0);
        HAL_UART_Receive_IT(huart, rx_buffer, sizeof(rx_buffer));
    }
}
```

## Important Design Notes

### FreeRTOS Heap is Tight (3 KB)

Budget your task stacks carefully:
- `defaultTask`: 128 words = 512 bytes
- `PIRTask` (proposed): ~256 words = 1 KB
- `TimerTask` (proposed): ~256 words = 1 KB
- Total: ~2.5 KB, leaving ~500 bytes headroom

If tasks run out of heap: increase `configTOTAL_HEAP_SIZE` in `FreeRTOSConfig.h` (check available RAM).

### Dual-Core Implications

The M0+ core runs the BLE radio stack. Do not:
- Use GPIO pins or UART reserved for M0+ (check M0+ firmware)
- Block FreeRTOS calls from BLE callbacks
- Disable M0+ clock or interrupt routing

### Clock Configuration is Conservative

MSI @ 4 MHz prioritizes power efficiency. To increase speed:
- Change `RCC_MSIRANGE_10` to a higher range in `SystemClock_Config()`
- STM32WB55 supports up to 64 MHz with PLL
- Monitor power consumption and thermal output

### No Floating-Point in ISRs

FPU is disabled (`configENABLE_FPU = 0`). If floating-point math is needed:
- Enable in `FreeRTOSConfig.h`
- Rebuild with `-mfloat-abi=hard -mfpu=fpv4-sp-d16`
- Use FP only in tasks, never in ISRs
